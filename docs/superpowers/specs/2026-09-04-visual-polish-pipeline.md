# 畫面精緻度規格與 AI 美術生產流程

- 日期：2026-09-04

## 0. 核心命題

**精緻度不來自單張貼圖的細節量，來自少數幾個系統性效果被一致地套用。**

在 128×128 的尺度下，單張貼圖再多的筆觸細節都會被縮掉；但陰影、光源方向、色彩分級、環境動態、打擊感是**全域的**——一次做好，套用到所有資產，而且成本不隨資產數量增加。

**這對本專案特別關鍵**：美術為 AI 生成，而 AI 最不擅長的就是一致性。系統性效果恰好是把不一致的資產拉回同一個世界的工具。換句話說，這些效果不是「錦上添花」，是**補救 AI 生成先天弱點的主要手段**。

## 1. 精緻度的五層（依投報率排序）

投入順序即為下表順序。**在前一層驗收通過前，不做下一層。**

### L1　接觸陰影

| | |
|---|---|
| 做什麼 | 每個單位、塔、建物、樹底下一個柔邊橢圓陰影 |
| Godot | 單張共用的橢圓貼圖，`Sprite2D` 掛在單位下方，隨 y 座標微調長寬與濃度 |
| 成本 | 一張貼圖、幾行程式。**近乎為零** |
| 收益 | **最高**。沒有接觸陰影的單位看起來像貼紙浮在地上，這是業餘感最主要的來源 |
| 驗收 | 任一單位站在任何地形上，都能一眼看出它「站在」而非「貼在」畫面上 |

飛行／水面單位陰影拉遠並淡化，即可免費表達高度差。

### L2　統一光源方向

| | |
|---|---|
| 做什麼 | 全遊戲光源固定自**左上方**，投影短而硬（亞熱帶正午） |
| Godot | 不需程式。**這一層的成本全在 prompt 與驗收**，屬美術管線 |
| 成本 | 低，但需紀律 |
| 收益 | 高。光源方向不一致是 AI 生成資產集**最明顯的破綻**，而且人眼在單張圖上看不出來，要到十幾張擺在一起才發現 |
| 驗收 | 把當前所有單位並排一列，高光全在同一側 |

Prompt 固定加入：`light from upper left, short hard cast shadow to the lower right`。

### L3　全域色彩分級

| | |
|---|---|
| 做什麼 | 全螢幕後處理，把畫面拉進限定色域 |
| Godot | `CanvasLayer` 上一個全螢幕 `ColorRect` + 片段著色器（飽和度、色階、輕微色偏），或 `Environment` 的 adjustment |
| 成本 | 一支簡短 shader。**手機端幀率成本須實測**，併入 M2 |
| 收益 | **最高的單點槓桿**。這是讓一批來源不一的 AI 資產看起來像同一款遊戲的關鍵手段 |
| 驗收 | 關閉分級與開啟分級的畫面並排，開啟後色彩明顯收斂到色票 |

同一支 shader 可順帶承載關卡氛圍差異——1-3 的封鎖階段只要調參數就能變冷、變灰，不需重畫任何資產。

### L4　環境動態

| | |
|---|---|
| 做什麼 | 水面波光、樹梢搖擺、旗幟飄動、沙塵、飛鳥 |
| Godot | `AnimationPlayer` 或頂點位移 shader；粒子走 `GPUParticles2D` |
| 成本 | 中。每種動態要單獨做 |
| 收益 | 高。**靜止的畫面無論美術品質多好都顯廉價** |
| 驗收 | 暫停所有單位後，畫面仍在動 |

優先序：水面 > 植被 > 旗幟 > 粒子。本作是海戰關卡，水面動態的收益遠高於其他。

### L5　打擊感

| | |
|---|---|
| 做什麼 | 槍口閃光、後座位移、命中白閃、擊退、碎屑粒子、輕微震屏、命中音 |
| Godot | 全部走物件池（架構規格 §4.4）。震屏用 `Camera2D` offset，須可在設定中關閉 |
| 成本 | 中高。但**這是玩家口中「精緻」的八成來源** |
| 收益 | 極高 |
| 驗收 | 把所有貼圖換成純色塊，光看打擊感仍應覺得好玩 |

**最後這條驗收標準是判斷投資順序的準則**：如果純色塊版本不好玩，貼圖再精緻也救不了。

## 2. AI 美術的真正問題：風格漂移

問題不是單張品質不夠，而是**三十張擺在一起不像同一款遊戲**。而且這個問題有延遲——單張看不出來，要累積到十幾張才顯現，此時已經產出一批廢圖。

### 對策

1. **先建立黃金母本集**：20–30 張人工嚴格挑選過的定調資產。在母本集確立前，不量產。
2. **之後一律用參考圖條件生成**，不用純文字 prompt。文字 prompt 的變異性是風格漂移的主因。
3. **母本集穩定後可訓練 LoRA**。本地訓練，零成本，是把風格鎖死最有效的手段。
4. **同一單位的多個動作固定 seed**，確保各幀之間是同一個角色。
5. **大量生成 → 嚴格篩選（10 選 1）**，不要靠修圖搶救。修圖會製造新的不一致，而且單人做不完。
6. **統一後處理**（見 §3）。

## 3. 後處理管線

**每張圖進 `game/assets/` 之前必須過同一條管線。這條管線應該是一支腳本，不是手工。**

```
art_src/ 生成原圖
  ↓ ① 去背與裁切
  ↓ ② 色票量化 —— 映射到 art-direction-bible §2.1 的限定色域
  ↓ ③ 描邊統一 —— 程式加，不靠 AI 畫
  ↓ ④ 縮放至 128 並檢查剪影可讀性
  ↓ ⑤ 打包 Sprite Atlas
game/assets/
```

**第 ② 與 ③ 步是重點**：色票量化把不同批次的色偏強制拉齊；描邊由程式統一加上，可保證粗細與顏色一致——這正是 AI 畫不穩的兩件事，交給程式做即可根除。

理由與架構規格 §5.3 的資料完整性測試相同：**在 AI 協作下，只有能自動驗證與自動執行的東西才不會腐化。**

### 建議的自動檢查

沿用架構規格 §5.3 的測試框架，新增：

- **色票一致性**：掃描 `game/assets/` 所有 PNG，出現限定色域外的色相即測試失敗
- **剪影可讀性**：將貼圖壓成純黑剪影後縮至 32px，與同陣營其他單位比對相似度，過高即警告
- **尺寸與幀數**：超過 128×128 或動作幀數超出 6–8 即失敗

## 4. 開發順序：灰盒優先

**絕對不要美術先行。**

```
① 灰盒       純色塊，把數值與路徑調到好玩
② 剪影版     用純黑剪影確認 128px 下的可讀性
③ 上色版     套色票
④ 效果層     L1 → L5 依序疊加
```

**理由**：塔防的樂趣完全來自數值、路徑與節奏，與美術無關。美術先行的後果是玩法一改，資產全部作廢——而這在垂直切片階段是必然會發生的。

第 ② 步的剪影版常被跳過，但它是最便宜的保險：剪影不可讀的角色，上完色也不會可讀，而此時重畫的成本已經是十倍。

## 5. M2 閘門的擴充

架構規格 §9 已訂 M2 為效能閘門。建議把精緻度相關項目一併納入，避免二次驗證：

| 項目 | 來源 |
|---|---|
| 150 單位穩定 60fps | 既有 |
| 記憶體佔用實測 | 既有 |
| **色彩分級 shader 開啟後的幀率成本** | 新增（L3） |
| **粒子與震屏在同屏峰值下的幀率成本** | 新增（L5） |
| **潮汐色溫位移：shader 或雙貼圖的記憶體差** | 新增（1-1 待決策） |
| **色票一致性測試通過** | 新增（§3） |

## 6. 明確不做的事

| 不做 | 理由 |
|---|---|
| 2D 法線貼圖光照 | AI 產不出可用的法線圖，手工繪製成本過高，且手機端不划算 |
| 骨骼動畫 | 架構規格 §4.7 已排除 |
| 逐張手工修圖 | 單人做不完，且會製造新的不一致 |
| 追求單張貼圖的細節量 | 128px 下會被縮掉，投報率最低 |
| 高解析度資產「以備日後」 | 記憶體風險已是 M2 的主要疑慮，不預先加碼 |

## 7. 待決策事項

1. **色彩分級 shader 的幀率成本**在中階 Android 上是否可接受。若不可接受，備案是把分級直接烘進資產（後處理第 ② 步強化），失去執行期調氛圍的能力。
2. **LoRA 訓練的時機**。太早訓練會把未定案的風格鎖死；太晚則已產出一批漂移資產。建議在黃金母本集達 25–30 張且風格連續三批穩定後執行。
3. **震屏是否預設開啟**。對打擊感貢獻大，但部分玩家不適。傾向預設開啟並在設定中提供關閉。
