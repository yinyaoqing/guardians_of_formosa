# A2x　風格實驗：戰場皮影、過場版畫、風格搬到 shader

- 日期：2026-09-08
- 性質：實驗，**不是決定**。目的是用最少成本回答「若再進一步線條化、把風格搬到執行期，美術依賴能降多少」。
- 相關討論：美術聖經 §1.1 的區隔點、精緻度規格 L3、架構規格 §4.7 的逐格動畫決定

---

| 檔案 | 用途 |

## 2. 結果

### 2.1 皮影單位：成立

FLUX.2 Klein 4B 純文字、每資產 2 張、與 chapter01 相同管線，三個單位全部一次可用：

- 嚴格側面、單人、素底——構圖遵循度比 3/4 視角穩得多
- 三個關鍵細節全到位：銃卒三角笠盔 + 赤足、鏢手長鏢對角線 + 藤黃腕帶、鐵人札甲格紋 + 背後藤牌 + 赤足
- 鏤空格紋確實出現，線條粗細均勻，色域幾乎全在色票內，量化後沒有可見斷階
- **1:1（128px）下三者的剪影一眼分得開**：水平長槍／長對角線／寬矩形——比現況的 3/4 視角版更清楚

沒到位的：鐵人仍缺鐵面罩、盔形偏歐（與 A1 §9.3 同一個知識缺口，換風格不解決它）；頭身比約 5–6，皮影的「大頭」沒出來。

### 2.2 一個管線發現：量化會吃掉深紅

銃卒的第一張候選是暗紅（近 `#7B2A20`），`quantize()` 把它映射到深赭／焦茶，**硃砂號衣在 128px 上變成褐色，陣營識別色消失**。第二張候選較亮才保住。這與風格無關，是既有量化器的問題：色票的紅色只有 `#B5442E`／`#A8332B` 兩個亮階、沒有暗階，任何陰影紅都會掉到褐色。建議補明暗階（見上一輪檢討第四節第 3 點）。

### 2.3 版畫過場：媒介成立，內容要防

「木刻版畫」的媒介感一次到位：粗刀線、紙底、套色感，讀起來就是印刷品。**但衛兵被畫成 20 世紀殖民地警察**（大盤帽、長靴、佩刀）——「1940s East Asian woodblock movement」把日治時期的先驗一起帶進來了。這是 A1 §7.4 的鏡像：媒介對了，年代錯了。修法是在 subject 把衛兵寫成 17 世紀 VOC 火繩槍手的具體形制，並在 style 拿掉年代詞、只留刀法描述。

### 2.4 shader：要分兩層

第一版把描邊 + 紙紋做成單一全螢幕 pass，蓋在所有東西上。結果 **128px 上量化出來的格紋每個像素邊都被 Sobel 抓成墨線**，鐵人的札甲糊成一團（`xp_paper_ink_single_layer.png`）。

改成兩層後成立：

```
layer 40   描邊 + 紙紋   ← screen texture 只看得到地圖，地圖收成線稿
layer 50   單位           ← 輪廓由 postprocess.py 統一加好，不再吃 Sobel
layer 100  只有紙紋       ← 讓單位也躺在紙上
```

這其實是規格內部一致的結論：精緻度規格 §3 說外輪廓由程式加、保證粗細一致；那麼執行期的描邊就不該再碰單位。**單位靠管線描邊，場景靠 shader 描邊，紙紋蓋全部。**

## 3. 對「降低美術依賴」這個問題的回答

| 成本項 | 皮影 + shader 路線 | 依據 |
|---|---|---|
| 一致性 | 大降 | 色數少、輪廓粗、側面固定，三張一次可用且並排看不出批次差 |
| 內容正確性 | 小降 | 細節少了但形制還是得對——鐵人的面罩照樣缺 |
| 動畫幀數 | **尚未驗證** | 皮影分件動畫的前提是「同一角色的分件圖」，本實驗只做了整體圖。這是下一個該做的實驗 |
| 場景 | 大降 | 地圖過 shader 後自動線稿化，場景資產的精緻度要求可以降到「形狀與色塊對」 |

**下一步該做的實驗（依序）**：
1. 皮影分件：同一 prompt 加「puppet parts laid out flat: head, torso, upper arm, forearm, thigh, shin, weapon」看 FLUX.2 能否給出可組裝的分件；或用 Klein 的多參考圖編輯從整體圖拆件
2. 量化器補明暗階，重跑三張看硃砂是否保住
3. 版畫 prompt 拿掉年代詞、衛兵改寫形制，重出一張
4. 以上都成立後，才值得回頭改美術聖經 §1.1 與架構規格 §4.7

## 4. 追加實驗：像素呈現 + TileMap 地圖（同日）

使用者提出參考圖（Guardian Towers 類的像素 TD）。先拆解那類畫面好看的原因：路徑與地面高對比、地圖是重複擺件拼的、每個東西底下有接觸陰影、色數少無雜訊、單位小但描邊統一。**這五條都是設計紀律，不是像素本身。** 故實驗設計為「呈現層開關」而非換風格。

| 檔案 | 用途 |
|---|---|
| `art/scripts/postprocess.py` | 新增 `--size-scale`、`--out`：同一批原圖縮到一半另存 `03_processed_px/`，不動正式產出 |
| `art/scripts/make_tiles.py` | 以色票程序化畫 32px 地磚（草地／沙洲路徑／水）與接觸陰影橢圓。地磚不用 AI——無縫磚是擴散模型最弱的項目，平色地面用程式畫更穩 |
| `art/manifest/experiment_props.json` | 榕樹、竹叢、礁石、林投四個擺件（chapter01 沒有獨立的樹） |
| `game/fx/pixel_demo.tscn/.gd` | SubViewport 960×540 最近鄰放大 2 倍；TileMapLayer 在執行期由圖集組成；擺件與單位走 y_sort、每個底下一個 L1 陰影 |

截圖：`art_src/contact/xp_pixel_tilemap.png`。

### 4.1 結果

- **地圖可讀性差距是本日所有實驗裡最大的。** 沙洲黃路徑在翠綠地面上一眼看出走向；同一批單位放在 `map_1_1` 上要找。這與像素無關，`map_1_1` 換成 TileMap 就有。
- **64px + 最近鄰 2 倍**：單位在螢幕上與 128px 1 倍同大，細節少一半但仍可辨（笠盔、赤足、長鏢都在）。與參考圖相比我們的單位仍偏大——參考圖單位約 24–32px。要那種密度得再縮一半，屆時赤足這類設計點會消失。
- **擺件**：FLUX.2 一次出四個可用；重複擺放後畫面密度感立刻出來，這正是參考圖的做法。
- **地磚邊緣是方的**，參考圖的路徑邊緣有機。若採用，補 autotile 過渡磚（人畫，每種地形 16 格以內）。

### 4.2 又一個量化器的問題：鐵灰是陷阱

榕樹樹冠 `#416A53` 被量化成**鐵灰 `#5A5A5E`**——RGB 距離 32，比榕蔭綠的 34 近。鐵灰是鐵人軍的陣營色，卻是色票裡唯一的中性灰，在 RGB 空間裡坐在正中間，任何低飽和的中間色都會被它吸走。這與 §2.2 硃砂變褐色是同一類問題：**用 RGB 歐氏距離做最近色，不看色相。** 建議 `quantize()` 改在 Oklab 或加色相權重比較，並把鐵灰限定只對 `fac=ironman` 開放。本次示範用 `--no-quantize` 繞過榕樹。

### 4.3 對「像素風是否更好」的回答

更好的部分（路徑對比、擺件拼貼、接觸陰影、小色數）**全部不需要像素**，只需要把地圖從整圖改成 TileMap 並做 L1。像素放大本身帶來的只有「藏瑕疵」與「幀可手修」兩項，代價是史實細節與辨識度。**建議：地圖改 TileMap 是不管選什麼風格都該做的事；像素放大保留為呈現層開關，等單位尺寸定案再決定。**

## 5. 追加實驗：無五官的扁平幾何人物（同日）

使用者提出 Reigns 類卡牌肖像（扁平幾何、左亮右暗分光、無五官）與扁平長影圖示。清單：`art/manifest/experiment_faceless.json`（四張肖像 + 一張全身銃卒，`xp_face_` 前綴）。印樣：`art_src/contact/xp_faceless_portraits.png`、`xp_faceless_unit.png`。

### 5.1 結果

- **媒介一次到位**：扁平色塊、垂直分光線、無描邊、色域全在色票內。四階膚色（美術聖經 §2.1）在無五官的臉上成為最大的視覺元素——揆一淺膚、陳澤中膚、頭目深膚、奴工極深膚，一眼可分。這是章節規格 §2.5 在美術上最清楚的一次落實。
- **「無五官」的遵循度分兩種**：全身圖 2/2 完全無五官；肖像 8 張裡只有 2 張完全無五官，其餘帶閉眼短線、眉毛或淡嘴線。擴散模型對特寫臉有「必須畫眼睛」的先驗，正向描述壓不住。**但參考圖本身就是兩條短線當眼睛**，這個結果其實比「全空」更接近參考。若要全空，臉是一整塊平色，程式抹掉細短筆畫（限定在膚色區內做形態學開運算）是可行的後處理，不必靠模型。
- **形制**：揆一的黑衣白翻領、陳澤的盔纓與山文甲、頭目的銀頭藤杖與耳飾、奴工的布帶與負重全部到位；銃卒笠形盔 + 赤足 + 火繩槍到位。錯的有：頭目一張戴了帽（規格：無帽）、揆一一張戴了高頂帽（年代不對）、陳澤的盔偏日式——都是 A1 已知的知識缺口，不是風格問題。

### 5.2 對規劃的意義

這個風格可以把「戰場單位／對話肖像／圖示」收斂成**同一套語彙**，比「皮影 + 版畫」少一種媒介：
- 拿掉 AI 最不穩的三樣東西（眼、嘴、手），一致性由風格本身保證，A3 的 LoRA 幾乎不需要
- 分光線就是 L2 的幾何化執行，`check_lighting.py` 的不一致問題結構上消失
- 扁平幾何是最容易做分件／Tween 動畫的形態，與分件路線相容（像素風不相容）
- 倫理判準（美術聖經 §0）：無五官必須**一視同仁**——殖民者也沒有臉。只要不出現「歐洲人有五官、其他人沒有」的差別，站得住

風險：與 Reigns 的相似度要刻意用色票、帽盔形制、背景拉開；圖示的石板底框應由 UI 主題畫一次，AI 只出中間的符號。

## 6. 行走循環實測：逐格 vs 分件（同日）

目的：用一個單位（鄭軍銃卒）各做一套 4 幀行走循環，比較「做出可播放的循環要花多少」，作為架構規格 §4.7（逐格 vs 分件）的決策依據。

| 檔案 | 用途 |
|---|---|
| `art/workflows/a2x_flux2_edit.api.json` | FLUX.2 Klein 參考圖編輯（`ReferenceLatent`），接法照 ComfyUI 官方藍圖 |
| `art/scripts/walk_frames.py` | 餵母本圖，逐幀改 prompt（接觸／經過 × 左右）產「同一角色」的 4 幀 |
| `art/scripts/walk_pack.py` | AI 幀對齊打包（不 trim、整畫布等比縮）；皮影母本拆軀幹 + 兩腿，寫出髖關節 pivot |
| `game/fx/walk_demo.tscn/.gd` | 四列並排：A 逐格扁平幾何 128、B 同批幀 48px 最近鄰、C 逐格皮影 128、D 分件皮影程式擺動 |

截圖：`art_src/contact/xp_walk_cycle.png`（左＝動態幀，右＝四幀攤開）。

### 6.1 逐格（Klein 參考圖編輯）

**角色一致性一次解決。** 帽、衣、槍、手、鏤空格紋逐幀完全同一個人——A1 §7.5 用 SDXL 五種機制全失敗的「同一角色換姿勢」，Klein 一個節點成立。這推翻了美術聖經 §7.4「幀間連貫必須靠 Blender 粗模共用幾何」的前提。

**姿勢控制是新的弱點。** 接觸姿勢（跨步）幀幀正確；經過姿勢（雙腿併攏、抬膝）扁平幾何版畫出怪膝蓋，皮影側面版根本沒併攏——四幀幾乎都是跨步，播起來是拖著走。逐格的成本從「角色會變」轉成「每幀要挑」，估每幀 3–5 選 1。

成本：8 幀 GPU 約 12 分鐘、腳本與 prompt 約 1 小時。單位 × 動作 × 幀數仍是乘法。

**48px 最近鄰**：怪膝蓋被藏掉一半，仍看得出。「像素藏瑕疵」成立但不是免死金牌。

### 6.2 分件（拆件 + 程式擺動）

母本用固定切線拆成軀幹 + 兩腿（衣襬蓋住接縫），腿繞髖關節正弦擺動 ±28°、軀幹起伏 2px。**一小時內做出可播放的循環，零 GPU**，且所有單位共用同一段程式——幀數不再是成本變數，攻擊／受擊只是換一組角度曲線。

限制：只有旋轉，沒有形變——做不出抬膝、轉身、倒地；每個單位要人標一次切線與 pivot（約 5 分鐘）；執行期每單位 3 個 Sprite2D，150 單位＝450 個繪製項，M2 應量。

### 6.3 又是量化器

扁平幾何的硃砂衣在 128px 上第三次變成褐色（`#8B3A35` → 深赭 `#8C3A22`）。三次同一個問題，該修了：色票補暗階或改 Oklab 距離。

### 6.4 建議

- **戰場單位走分件**，皮影或扁平幾何皆可（兩者都是平面色塊，拆件友善）。逐格保留給旋轉表達不了的動作（倒地、轉身），用 Klein 編輯產、每幀挑。
- **Klein 參考圖編輯升格為正式產線工具**：產同角色的替代姿勢、拆件用的分件圖、以及肖像。美術聖經 §7.4 的 Blender 粗模路線可以撤。
- 架構規格 §4.7「不用骨骼動畫」的理由（AI 產不出透視一致的分件）在平面風格下不成立，應改寫為「分件動畫，平面拆件」。
- 先修量化器，再繼續任何母本審查——三個實驗都被它咬到。

## 7. 修量化器 + 分件動畫接進戰場（同日）

### 7.1 量化器

`quantize()` 改用 **Oklab 距離**，並把**鐵灰改為選擇性**：預設不參與量化，只對清單裡明列 `"allow": ["鐵灰"]` 的資產（鐵人軍）開放。實測：

| 顏色 | 舊（RGB） | 新（Oklab、無鐵灰） |
|---|---|---|
| 榕樹樹冠 `#416A53` | 鐵灰 ✗ | 榕蔭綠 ✓ |
| 陰影紅 `#7B2A20` | 深赭（褐） | 仍是深赭 |

第二列說明**暗紅不是距離算法的問題，是色票沒有暗的紅**——深赭是紅瓦赭的陰影階，但它偏橙褐，硃砂沒有自己的陰影階。故色票補一階 **硃砂暗 `#7A2A24`**（美術聖經 §2.1 已同步），之後 `#7B2A20`／`#7A2E2A` 落到硃砂暗，`#8B3A35`（偏亮）仍落深赭，屬合理。

`data/art_palette.json` 是量化器與 GdUnit 色票測試的共用來源，補色只改一處。

### 7.2 分件動畫進 `EnemyView`

- `EnemyView` 從 `Sprite2D` 改為 `Node2D`：敵人定義有 `"puppet"` 就依 `data/puppets/<id>.json` 建分件，否則維持單張貼圖。API（`setup`／`on_tick`／`interpolate`）不變，`battle_scene.gd` 只多傳一個參數。
- 相位由**走過的距離**推進（`stride_px` 像素一圈），速度變步頻跟著變，不需要幀；往左走整個節點水平翻轉。
- `walk_pack.py --install <name>` 把拆件貼圖裝進 `game/assets/puppets/<name>/`、定義寫進 `data/puppets/<name>.json`。
- 新敵人 `zheng_musketeer`（數值暫沿用 orc_grunt），`battle_scene` 改生它；`test_data_integrity` 新增 `test_every_enemy_puppet_is_well_formed` 守分件定義與貼圖存在。

踩到的坑：新加的 PNG 與 CSV 在 headless 測試前要先 `godot --headless --import`，否則 `ResourceLoader.exists()` 對未匯入的檔案回 false、翻譯檔也不會重生。

## 8. 版畫 prompt 修訂重出（同日）

依 §2.3 的修法重出：style 拿掉「1940s East Asian woodblock movement」只留刀法描述；subject 把衛兵寫成 17 世紀 VOC 火繩槍手的具體形制（寬邊氈帽、亞麻衫、及膝馬褲、木藥管彈藥帶、火繩槍，並明寫 NOT peaked caps／NOT boots）。

**結果：好一半。** 大盤帽消失、寬邊帽與彈藥帶出現；但衛兵仍是 20 世紀殖民地軍警的體態與皮帶配置（Sam Browne 式斜帶、彈藥包、長靴），一張的火繩槍畫成上刺刀的步槍；旁觀的西拉雅長老也被穿上襯衫馬褲。**「福爾摩沙 + 版畫」這個組合本身就把日治時期的先驗拉進來**，負面詞與形制描述都壓不完全。

規格層面的結論：敘事大圖的內容正確性不能只靠文字。§6 已證明 Klein 參考圖編輯能鎖住角色——**下一步應該把 §5 產出的無五官肖像（揆一、頭目、奴工）與 chapter01 的 VOC 火槍手當參考圖，用 `a2x_flux2_edit` 的多參考圖編輯合成場景**，讓「誰穿什麼」由參考圖決定、版畫媒介由 prompt 決定。這與 A1 §7.4 的教訓一致：內容靠圖、風格靠字。

另：兩色套印（terracotta + jade）仍沒出現，產出是全彩木版畫。若要嚴格雙色，交給後處理量化到四色即可，不必靠模型。

### 9.3 重跑比對：Oklab 被否決，RGB + 兩個針對性修正

先用 §7.1 的 Oklab 版重跑 33 張與 `game/assets/chapter01` 逐像素比對（`art_src/contact/requantize_diff.json`）：每張 15–50% 像素改變，並排看有**三個回歸**——藤黃火焰／旗幟被拉成曝曬沙（陣營標記色消失）、奴工的極深膚被拉成硃砂暗（美術聖經 §2.1 明列的「壞掉」）、鐵人的鐵灰幾乎消失。Oklab 的距離由明度主導，對本色票這種「色相分得開、明度擠在一起」的小色票反而更差。

用真實像素樣本測 RGB／Oklab／Oklab 加色度權重 2–8 倍，沒有一種變體全對。**改回 RGB 距離，只保留兩個針對性修正**（鐵灰改選擇性、色票補硃砂暗）：兩個原始問題（榕樹掉鐵灰、暗紅掉褐）都解掉，樣本裡沒有回歸。`postprocess.py --metric oklab` 留作實驗選項。

RGB 版重跑的差異落在 5–28%（鐵灰被吸走的陰影像素回到正確色相），視覺上一致。**兩張差異異常的是候選來源問題，不是量化器**：
- `enemy_ironman` 92%：母本集是從 2 張候選挑的，A2 Task 3 之後 `stage_flux2` 有 10 張，`postprocess` 取 `files[0]` 已是另一張。
- `enemy_warjunk` 140%：**`game/assets` 裡是被拒絕的歐式蓋倫船**，正確的中式硬帆在 `stage_a`。`source_stage` 的釘死（`5ac00a0`）晚於資產進 `game/assets`（`3fee8fa`），舊圖沒被換掉。

兩者都不在此時修：母本集即將整批換成扁平幾何風格重挑，屆時一併處理。教訓寫下來：**母本的候選來源必須記錄在清單裡**（A2 Task 4 的 `master_set.json` 尚未實作），否則「重跑」根本無法對到同一張圖。
